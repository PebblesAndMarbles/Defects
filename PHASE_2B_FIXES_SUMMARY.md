**Date**: 2026-07-06  
**Status**: ✅ COMPLETE - Ready for re-run

### Root Cause Analysis

The NCDD_EDI source CSVs from the JMP query contain **separate rows** for each metric type:
- **NCDD rows**: BEEP_NCDD, SMP_NCDD have values → EDI columns are null
- **EDI rows**: BEEP_EDI, SMP_EDI have values → NCDD columns are null
- Same wafer key, different metric classifications (expected JMP behavior)

The original `merge_and_dedup_raw_sources()` function deduped by wafer key only, causing data loss:
- When keep="last" was applied to wafer-keyed duplicates, either the NCDD or EDI row was dropped
- This resulted in 158-162 rows with null NCDD metrics but valid EDI metrics
- Pipeline then computed CLASS_BEEP="UNKNOWN" for these rows (from null BEEP_NCDD)

### Fixes Implemented

#### 1. ✅ Restored Production CSVs
- Replaced corrupted files with clean backups from Desktop
- **8M5CL_8M6CL_EXTENDED_60DAY.csv**: 1,055 rows (clean)
- **8M5CL_8M6CL_EXTENDED.csv**: 10,972 rows (clean)
- Verified: 0 UNKNOWN rows, 0 EDI-only corrupted rows

#### 2. ✅ Fixed EXTEND_BENCHMARK.py merge_and_dedup_raw_sources() function
**Location**: Lines 145-238  
**Changes**:
- Added detection for dual-metric NCDD_EDI source files
- Splits data into separate NCDD and EDI DataFrames based on metric column presence
- Deduplicates each metric set independently (keep="last")
- Performs full outer join on wafer key to preserve BOTH metrics
- Consolidates overlapping columns back together
- Preserves single-metric source backward compatibility

**New Logic Flow**:
```
Dual-metric source detected
  ├─ Split NCDD rows: X rows (BEEP_NCDD not null)
  ├─ Split EDI rows: Y rows (BEEP_EDI not null)
  ├─ Dedup NCDD separately: X → A rows
  ├─ Dedup EDI separately: Y → B rows
  └─ Outer join on wafer key: (A + B - overlap) rows
```

#### 3. ✅ Updated defect_processor.py _finalize_dataframe() method
**Location**: Lines 698-712  
**Changes**:
- Added cleanup to remove 9 unwanted EDI-derived columns
- Executes before sorting/column ordering
- Columns removed:
  - STATUS_EDI, CLASS_EDI, ZERO_EDI
  - STATUS_BEEP_EDI, CLASS_BEEP_EDI, ZERO_BEEP_EDI
  - STATUS_SMP_EDI, CLASS_SMP_EDI, ZERO_SMP_EDI

**Why**: These columns should not be generated by the pipeline (they're intermediate artifact columns from the ColumnManager; final output should only have NCDD and EDI base metrics + SUM_NCDD and SUM_EDI)
