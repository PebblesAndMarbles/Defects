## Bugs Encountered

### BUG-001: Manifest CLASS column misread as inspection recipe (SMP/BEEP detection)
- **Status:** Resolved
- **File(s):** `html\INLINE_CHAMBER_EVENT_REPORT.py`, `html\INLINE_PRODUCTION_SUBENTITY_REPORTS.py`
- **Root Cause:** The manifest CLASS column holds defect class (often NaN), not the inspection recipe type. Code was reading CLASS to determine SMP vs BEEP.
- **Fix Applied:** Parse SMP/BEEP from the image filename string instead of the CLASS column.
- **Notes:** This caused all RECENT_LOTS_7D image slots to be mis-assigned or blank.

### BUG-002: Missing SUBENTITY / LOT7 in recent manifest rows
- **Status:** Resolved
- **File(s):** `html\INLINE_CHAMBER_EVENT_REPORT.py`
- **Root Cause:** Recent manifest rows have ~100% null values in metadata columns (SUBENTITY, LOT7, etc.) — metadata backfill has not yet caught up.
- **Fix Applied:** Infer SUBENTITY from the image file's parent folder name; infer LOT7 from field 3 of the filename.
- **Notes:** This is a known data quality gap in the manifest pipeline; the inference is reliable for current naming conventions.

### BUG-003: Missing WAFER_X_MM / WAFER_Y_MM coordinates
- **Status:** Resolved
- **File(s):** `html\INLINE_CHAMBER_EVENT_REPORT.py`
- **Root Cause:** WAFER_X_MM and WAFER_Y_MM are also null for recent manifest rows for the same reason as BUG-002.
- **Fix Applied:** Two-tier coordinate join against `DEFECT_COORDINATES_EXTENDED.csv`: primary key = (WAFER_KEY, INSP_TIME, DEFECT_ID); fallback key = (SUBENTITY, LOT7).
- **Notes:** SVG wafermap dots will be absent for any defect that cannot be matched by either join tier.

### BUG-004: Orphan dead code body inside new function
- **Status:** Resolved
- **File(s):** `html\INLINE_CHAMBER_EVENT_REPORT.py`
- **Root Cause:** During refactor, the original function body was not deleted after being replaced — left as unreachable dead code inside the new function.
- **Fix Applied:** Dead code block found and deleted.
- **Notes:** Code was syntactically valid so no immediate error; would have silently produced wrong output.

### BUG-005: Unicode CP1252 crash on scheduled VM before recent-lots step
- **Status:** Resolved
- **File(s):** `html\INLINE_PRODUCTION_SUBENTITY_REPORTS.py`
- **Root Cause:** Print statements used `─` (U+2500 box-drawing), `—` (em-dash), and `→` (arrow). Scheduled task VM uses CP1252 encoding, which cannot encode these characters.
- **Fix Applied:** Replaced all non-ASCII characters in print statements with ASCII equivalents: `─`→`-`, `—`→`--`, `→`→`->`.
- **Notes:** The crash occurred before the recent-lots step was reached, making the bug invisible in normal dev runs. Affects any script run via scheduled task on this VM.

## Key Decisions Made
- **Pure SVG wafermaps** chosen over matplotlib to avoid 4+ minute hangs on dense chambers (e.g. AME421_PM3). matplotlib approach was explicitly rejected.
- **CSS Grid `repeat(auto-fill, 93px)`** for image layout: wafermap anchored at grid position [1-2, 1-2]; defect entries auto-fill right then below. 93px chosen to fit standard image thumbnails.
- **Dual-class defects** (`defect-entry--dual` CSS class) expand to 2-column width in grid; this handles reclassified defects where both original and new class images appear side-by-side.
- **`run_for_chamber` is the importable API** — external callers (batch runner, adhoc scripts) call this function; `run_recent_lots_report` is the cross-chamber companion.
- **Filename parsing for inspection type** — SMP_2/SMP_3 and BEEP_2/BEEP_3 determined from filename, not manifest CLASS column (BUG-001 fix is intentional and permanent).
- **Two-tier coordinate join** chosen over failing silently or raising; missing coords result in wafermap dots being absent rather than crashing the report.
- **ASCII-only print statements** as a permanent policy for scripts scheduled on the Intel VM, given CP1252 encoding constraint.
- **`docs/FLEET.txt` one-per-line format** chosen for maintainability; comment header added for context. 51 chambers match actual `images\defects\` subdirectories exactly.
